# Local setup for a fresh clone

A fresh clone runs locally in about 10 minutes. Nothing secret is committed; every value you need is listed here.

## 1. Prerequisites

| Tool | Version | Why |
| --- | --- | --- |
| Node.js | 22.12 or newer (`nvm use` reads `.nvmrc`) | API and client |
| Docker Desktop | any recent | PostgreSQL 16 and Redis 7 containers |
| Git | any | clone the repo |

No global installs beyond these. PostgreSQL and Redis can also be installed natively; then only `DATABASE_URL` and `REDIS_URL` change.

## 2. First run (copy-paste)

```sh
git clone <repo-url> && cd Wissen-Code
nvm use                                  # Node 22
npm install && npm run install:all       # root, server, client

npm run setup:local                      # creates server/.env + client/.env from the examples,
                                         # generates a random JWT_SECRET

POSTGRES_PASSWORD=wissen-local-dev docker compose up -d postgres redis

cd server
npm run db:generate                      # Prisma client
npx prisma migrate deploy                # creates all tables
npm run db:seed-users                    # demo accounts (below)
npm run db:seed                          # optional: sample questions, assessments, results
cd ..

npm run doctor                           # checks env, database and Redis connectivity
npm run dev                              # API on :4001, client on :3000
```

Open http://localhost:3000.

`POSTGRES_PASSWORD` must match the password inside `DATABASE_URL` in `server/.env`. The example uses `wissen-local-dev` for both, so the commands above work unchanged.

## 3. `server/.env` reference

`npm run setup:local` writes this file from `server/.env.example`. Required values are already filled for local use.

### Required

| Variable | Local value | Notes |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql://wissen:wissen-local-dev@localhost:5432/wissen_code?schema=public` | Append `&connection_limit=25` in production |
| `JWT_SECRET` | generated by `setup:local` | Long random string. Never share or reuse between environments |
| `REDIS_URL` | `redis://localhost:6379` | Sessions, OTP codes, BullMQ queues |
| `PORT` | `4001` | The client dev proxy expects this |
| `APP_URL` | `http://localhost:3000` | Used in email links |
| `CORS_ORIGINS` | `http://localhost:3000,http://localhost:5173` | Comma-separated, no trailing slash |
| `JUDGE_MODE` | `mock` | `mock` simulates code execution. Production refuses `mock` |

### Email (optional, needed for OTP, invitations, password recovery)

Nodemailer is used when either block is set, otherwise Resend, otherwise email is off.

| Variable | What to put |
| --- | --- |
| `MAIL_FROM` | Sender address, usually the same Gmail account |
| `MAIL_FROM_NAME` | `Wissen Code` |
| `MAIL_TIMEZONE` | `Asia/Kolkata` (times shown in emails) |
| `SMTP_HOST` / `SMTP_PORT` | `smtp.gmail.com` / `465` for Gmail |
| `SMTP_USER` | The Gmail address |
| `SMTP_PASS` | A Gmail **App Password** (Google Account → Security → 2-Step Verification → App passwords), 16 characters, no spaces. Not the account password |
| `GOOGLE_MAIL_USER`, `GOOGLE_MAIL_CLIENT_ID`, `GOOGLE_MAIL_CLIENT_SECRET`, `GOOGLE_MAIL_REFRESH_TOKEN` | Alternative to SMTP: Gmail OAuth2 from Google Cloud Console |
| `RESEND_API_KEY` | Alternative provider |
| `OUTBOX_INLINE` | Default on: the API sends queued mail every 10 s. Set `false` to rely only on `npm run worker:mail` |

Each developer uses their own Gmail app password. Do not share one.

### Code execution

| Variable | Notes |
| --- | --- |
| `JUDGE0_API_URL` | `https://ce.judge0.com` (public, heavily rate-limited) or your self-hosted Judge0 |
| `JUDGE0_API_KEY` | Only for RapidAPI-hosted Judge0 |
| `EXECUTION_CONCURRENCY` | Parallel "Run code" executions per process. `4` locally, `16` for a 300–400 candidate cohort |
| `GRADING_EXECUTION_CONCURRENCY` | Parallel executions for submit-time grading. Defaults to `EXECUTION_CONCURRENCY` |

### Grading and throttling

| Variable | Notes |
| --- | --- |
| `ASYNC_GRADING` | `0`: the API grades submissions in the background itself. `1`: a separate `npm run worker:grading` process grades (production) |
| `GRADING_CONCURRENCY` | Attempts graded in parallel, `2` locally, `8` for cohorts |
| `AUTH_RATE_LIMIT_PER_IP` | Login attempts per minute per IP, `600` (many candidates share one office IP) |
| `AUTH_RATE_LIMIT_PER_ACCOUNT` | Login attempts per minute per email, `20` |

### Other optional

| Variable | Notes |
| --- | --- |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | AI question generation. Needs `npm run worker` in a second terminal |
| `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` | Company SSO for staff |
| `WEBRTC_ICE_SERVERS` | JSON array of STUN/TURN servers for interview video |
| `ATS_WEBHOOK_URL`, `ATS_WEBHOOK_SECRET` | Signed webhooks to an ATS |
| `MONITORING_TOKEN` | Protects `/metrics` |
| `TRUST_PROXY` | `1` behind Caddy/Nginx |

### `client/.env`

| Variable | Notes |
| --- | --- |
| `API_PROXY_TARGET` | `http://localhost:4001`, Vite dev proxy |
| `VITE_API_URL` | Leave empty locally (defaults to `/api`) |

## 4. What works without the optional parts

| Not configured | Effect |
| --- | --- |
| Email | Sign-up still works (OTP shows "verify later"), invitations and password recovery mails are not sent |
| Real Judge0 | Code "runs" with simulated output, tests pass or fail deterministically by content |
| OpenAI | AI Questions page shows the feature as off |
| SSO | Only email + password login for staff |

## 5. Day-to-day commands

| Task | Command |
| --- | --- |
| Both dev servers | `npm run dev` (root) |
| Only API / only client | `npm run dev:server` / `npm run dev:client` |
| Health check | `npm run doctor` |
| Tests (server 26, client 69) | `npm test` (root). Server tests need `server/.env.test` from `.env.test.example` and a separate `wissen_code_test` database |
| Production build | `npm run build` |
| Mail worker (optional locally) | `npm run worker:mail` |
| Grading worker (when `ASYNC_GRADING=1`) | `npm run worker:grading` |
| AI worker | `cd server && npm run worker` |
| Load test (400 candidates) | `cd server && npm run db:seed-load -- 400`, then `node scripts/load-test.mjs --users 400 --duration 120`, then `npm run db:seed-load -- clean` |

## 6. Production notes

- `compose.production.yaml` runs API, AI worker, grading worker, mail worker, frontend and Caddy. Set `APP_HOST`, `POSTGRES_PASSWORD`, `JWT_SECRET`, `JUDGE0_API_URL`, mail variables and a real Judge0 before starting.
- `JUDGE_MODE=live` is mandatory in production; mock execution is refused.
- For 300–400 concurrent candidates: self-hosted Judge0 with roughly 16–24 workers, `EXECUTION_CONCURRENCY=16`, `GRADING_CONCURRENCY=8`, `connection_limit=25` on `DATABASE_URL`. Re-run the load test against staging first.
- Never commit `server/.env`, `client/.env` or `server/.env.test`. They are git-ignored; keep it that way.
